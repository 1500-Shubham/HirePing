# HirePing - Architecture Document

## Product Summary

HirePing is a subscription-based platform where tech job seekers upload their resume, and the system sends tailored cold emails to HR/Managers/CTOs -- generated by Gemini AI. Users manually trigger sends from the UI. In the MVP, emails are logged to the console rather than actually delivered via Gmail.

## Core User Flow

```
User Signs Up (Google OAuth)
       |
       v
Uploads Resume (PDF)
       |
       v
Backend saves PDF to temp disk, extracts text via pdf-parse
       |
       v
Text sent to Gemini API for structured extraction
       |
       v
Gemini returns JSON:
  {
    name, phone, location, summary,
    skills[], education[], experience[]
  }
       |
       v
Stored directly in MongoDB -> users collection (profile + resume.parsedData fields)
Temp PDF file is deleted after parsing
       |
       v
User reviews & edits profile in UI (skills, education, experience, etc.)
       |
       v
User selects target countries (e.g., INDIA, US, UK)
       |
       v
User purchases a plan (MVP: instant activation, no payment gateway)
  - Weekly: 200 INR -> 30 emails/day for 7 days
  - Monthly: 600 INR -> 30 emails/day for 30 days
       |
       v
User clicks "Send" button on Emails page:
  |
  +-- Check active plan & daily limit
  +-- Query sources WHERE:
  |     country IN user.selectedCountries
  |     isActive = true
  |     dailyEmailCount < 5  (global anti-spam cap)
  +-- Shuffle & pick up to (dailyLimit - sentToday) sources
  +-- For each source:
  |     +-- Generate tailored email via Gemini
  |     |   (input: user.profile + source info + last 5 emails for uniqueness)
  |     +-- "Send" email (MVP: log to console with fake messageId)
  |     +-- Increment source.dailyEmailCount
  +-- Update user.emailsSentToday & user.lastEmails (FIFO, keep 5)
  +-- Return results to frontend
```

## Source File Ingestion

Sources are loaded from the `sources/` folder at the project root (not uploaded via UI).

### How it works:
1. Drop `.txt`, `.csv`, or `.pdf` files into `sources/`
2. Country is extracted from the filename: `INDIA.txt` -> `INDIA`, `UK2.txt` -> `UK` (numbers stripped)
3. User or admin calls `POST /api/sources/sync`
4. Backend reads every file in `sources/`, parses rows, and upserts to MongoDB (keyed on email)

### File format (CSV):
```
name,email,role,company,companyType
John Doe,john@company.com,HR Manager,TechCorp,startup
```

- Header row is auto-detected and skipped if present
- If a row has a 6th column, it overrides the filename-based country
- Missing fields get defaults: role="HR", company="Unknown", companyType="startup"
- Invalid companyType values fall back to "startup"

### In Docker:
The `sources/` folder is mounted as a volume into the backend container (`./sources:/usr/src/sources`), so files can be added on the host and synced without rebuilding.

## Anti-Spam Algorithm

```
USER CLICKS "SEND" ON EMAILS PAGE

1. Check user has active plan (type != "none", expiresAt > now)
2. Calculate remaining = plan.dailyLimit - emailsSentToday
3. If remaining <= 0 -> return "Daily limit reached"
4. Get user.selectedCountries (must have at least one)
5. Query sources WHERE:
     country IN user.selectedCountries
     isActive = true
     dailyEmailCount < 5            <- GLOBAL CAP (no source gets >5 emails/day)
6. Shuffle results (Fisher-Yates) for randomness
7. Pick min(remaining, sources.length) sources
8. For each source:
     a. Generate email via Gemini:
        - Input: user.profile + source info + user.lastEmails (last 5)
        - Prompt ensures each email is unique and does not resemble previous ones
     b. "Send" email (MVP: console log with fake messageId)
     c. If success:
        - Increment source.dailyEmailCount += 1
        - Add to sentEmails batch
9. Update user:
     - emailsSentToday += sentEmails.length
     - lastEmails = [...old, ...new].slice(-5)   (FIFO, keep 5)
10. Return results to frontend

DAILY RESET (not automated in MVP):
  - source.dailyEmailCount needs manual or future cron reset to 0
  - user.emailsSentToday needs manual or future cron reset to 0
```

## API Routes

```
AUTH
  GET    /api/auth/google            -> Redirect to Google OAuth consent screen
  GET    /api/auth/google/callback   -> Handle OAuth callback, issue JWT, redirect to frontend
  GET    /api/auth/me                -> Get current user (requires JWT)
  POST   /api/auth/logout            -> Logout (client-side token removal)

PROFILE
  GET    /api/profile                -> Get user profile (name, email, avatar, profile fields)
  PUT    /api/profile                -> Update profile fields (phone, location, summary, skills, education, experience)

RESUME
  POST   /api/resume/upload          -> Upload PDF -> pdf-parse -> Gemini -> save to user.profile + user.resume

PLANS
  GET    /api/plans                  -> Get available plans (weekly: 200 INR, monthly: 600 INR)
  POST   /api/plans/purchase         -> Instant plan activation (MVP, no payment gateway)
  GET    /api/plans/status           -> Check plan status (active/expired/none, days remaining, emails remaining)

SOURCES
  POST   /api/sources/sync           -> Read sources/ folder, parse files, upsert contacts to MongoDB
  GET    /api/sources/countries      -> Get distinct countries with counts
  GET    /api/sources/stats          -> Get total contacts, breakdown by country and companyType

EMAILS
  POST   /api/emails/send            -> Manually trigger email sending (uses plan limit, anti-spam)
  GET    /api/emails/history         -> Get user's last emails + emailsSentToday count
  GET    /api/emails/stats           -> Get stats (totalSent, sentToday, remainingToday, planActive)
  PUT    /api/emails/countries       -> Update user's selectedCountries array

HEALTH
  GET    /api/health                 -> Health check (status, timestamp, environment)
```

All routes except auth and health require a valid JWT token in the `Authorization: Bearer <token>` header.

## Pricing (MVP)
